# CRM HERMES 4.3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publicar la 4.3.0 con temas de color, actualizaciones livianas con barra y botón de reinicio, carpeta de documentos por cliente, anualidad con felicitaciones, 7% con UF del día 5, etiquetas y filtros guardados, y la limpieza (campanita, código muerto, línea de la barra).

La interfaz (`public/`) consume todo por la API local.

**Tech Stack:** Electron 38.8.6, Express, sql.js, whatsapp-web.js 1.34.7 (con parches), electron-updater 6, `node:test`, zlib de Node.

**Spec:** `docs/superpowers/specs/2026-10-28-version-4-3-design.md`

## Review Focus

- **Paquete liviano roto o a medias** (corte de luz al extraer, sha512 distinto, versión que no arranca): el CRM debe abrir siempre, con la versión instalada si la liviana falla. Tarea 9 prueba `elegirArranque` con marcador de intento fallido y extracción atómica.

- **Mover a Ingresado dos veces / arrastrar por error**: no debe celebrar ni reiniciar la anualidad si ya hay una vigente. Tarea 5: test en `alCambiarEtapa`.
- **Sin internet el día 5**: el 7% debe seguir con la última UF guardada y reintentar. Tarea 4: test `fechaUFVigente` y que `necesitaUF` pida la del 5 cuando la guardada es de otro mes.

**Interfaces:**
- Produces (`anualidad.js`, fechas como `'AAAA-MM-DD'` locales):
  - `vigente(desde, hoy) → 'AAAA-MM-DD'`: el último aniversario ≤ hoy (avanza de a un año; 29-02 cae en 28-02 los años no bisiestos).
  - `estado(desde, hoy) → { desde, aniversario, aviso, mesesFaltan, progreso }` con `desde = vigente(...)`, `aniversario = desde + 1 año`, `aviso = aniversario − 30 días`, `progreso` 0..1.
  - `textoAviso({nombre, isapre}) → 'Aniversario de María Pérez (Colmena): revisar su plan'`.
- Produces (server): `alCambiarEtapa(antes, despues, ahora) → { iniciar: boolean }` (pura, en `anualidad.js`): `iniciar` es true solo si `despues.etapa === 'Ingresado'`, `antes.etapa !== 'Ingresado'` y `!antes.anual_desde`. Si ya tiene `anual_desde` (como se renueva sola, siempre está vigente), **no** se reinicia ni se celebra.
- `revisarAnualidades()`: para cada contacto con `anual_desde`: si `vigente(anual_desde, hoy) !== anual_desde` → guarda el nuevo `anual_desde` y fila `automatica`; asegura que exista un recordatorio `anual=1` no hecho con fecha `estado().aviso` (si hay uno con otra fecha, lo mueve). Idempotente.
- Renovar/fijar: reemplaza `anual_desde`, agrega fila al historial, mueve el recordatorio; si viene `isapre`, actualiza la del contacto.
